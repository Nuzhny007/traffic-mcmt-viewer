# Протокол WebSocket (v1)

Транспорт: текстовые кадры JSON, один объект на кадр. Координаты — `[lon, lat]`
в градусах WGS-84. Время — Unix time в миллисекундах (`timestamp` необязателен
для большинства сообщений). Клиент игнорирует неизвестные типы и битые кадры.

## `tracks_update`

Основное сообщение потока.

```json
{
  "type": "tracks_update",
  "timestamp": 1793776800000,
  "mode": "delta",
  "tracks": [
    {
      "global_id": 1042,
      "camera_id": 1,
      "class": "car",
      "position": [5.9742569, 45.5275189],
      "velocity": [11.85, -9.47],
      "speed_kmh": 42.66,
      "trail": [[5.9741, 45.5276], [5.9742569, 45.5275189]]
    }
  ]
}
```

- `mode`: `delta` (по умолчанию) — обновить/добавить перечисленные треки;
  `snapshot` — предварительно очистить буфер и заменить его содержимым `tracks`.
- `class`: `car | truck | bus | person | bike | unknown`.
- `velocity`: `[vx, vy]` в м/с, восток/север. Необязательно: C++ gateway
  опускает поле, пока в окне оценки меньше трёх точек.
- `speed_kmh`: модуль скорости в км/ч. Необязательное аддитивное расширение v1;
  если поля нет, клиент вычисляет `hypot(velocity) * 3.6`.
- `trail`: необязательная история `[lon, lat]`. C++ gateway передаёт её только
  при первом объявлении трека и в `snapshot`; в последующих `delta` поля нет,
  и клиент накапливает хвост сам из последовательных `position` (до 40 точек).
- `camera_zones`: необязательный список зон; если присутствует, заменяет
  текущий набор зон. C++ gateway присылает зоны отдельным сообщением.
- C++ gateway отправляет `tracks_update` только когда есть изменённые треки;
  в тишине кадров нет.

## `camera_zones`

```json
{
  "type": "camera_zones",
  "timestamp": 1793776800000,
  "camera_zones": [
    {
      "camera_id": 1,
      "polygon": [[5.9727, 45.52855], [5.97425, 45.52855], [5.97465, 45.5271]],
      "color": [239, 68, 68, 55]
    }
  ]
}
```

`color` — `[r, g, b, a]`, 0–255.

C++ gateway отправляет это сообщение один раз при подключении клиента, перед
`snapshot`. Полигон берётся из явного `cameras[].polygon` в `map_feed.yaml`
или строится как выпуклая оболочка контрольных точек `[points]` из
`geo_bind.ini`. Если у камеры нет ни того, ни другого, зона не отправляется.

## `id_merge`

Сообщает, что трек `old_id` переименован (ReID) в `new_id`. Клиент переносит
позицию и накопленный хвост на новый идентификатор.

В v1 `map_gateway` это сообщение пока не отправляет: слияние глобальных ID
появится в Master. Клиент уже готов к нему.

```json
{ "type": "id_merge", "old_id": 1042, "new_id": 100000 }
```

## `tracks_remove`

Аддитивное расширение v1: backend истёк трек и просит удалить его немедленно,
не дожидаясь локального TTL.

```json
{ "type": "tracks_remove", "timestamp": 1793776800000, "ids": [1042, 1043] }
```

C++ gateway присылает это сообщение, когда трек не получал наблюдений дольше
`feed.track_ttl_s` (по умолчанию 3 с). Клиент удаляет перечисленные
`global_id` из буфера. Если выбранный трек удалён, выбор сбрасывается.
Старые клиенты игнорируют неизвестный тип, а TTL остаётся страховкой.

## `emission_grid`

Аддитивное расширение v1 (этап 2c): поле концентраций Gaussian puff модели.

```json
{
  "type": "emission_grid",
  "timestamp": 1793776800000,
  "unit": "ug/m3",
  "bounds": { "west": 5.9704962, "south": 45.5252212, "east": 5.9781766, "north": 45.5292701 },
  "cols": 120,
  "rows": 90,
  "fields": {
    "NOx": { "data": "<base64>", "max": 569.193, "mean": 1.067, "p95": 238.173 }
  }
}
```

- `fields` — объект с ключами `NOx`, `CO`, `PM2.5`, `PM10`, `CO2`; отсутствующее
  поле просто не отображается.
- `data` — little-endian float32, `cols * rows` значений, row-major от южной
  границы к северной (первая строка — `south`), мкг/м³.
- `max`, `mean`, `p95` — статистика по всему полю в мкг/м³; используется для
  цветовой шкалы и панели.
- `bounds` — `west/south/east/north` в WGS-84.
- C++ gateway отправляет кадр с частотой `emissions.grid_hz` (по умолчанию
  1 Гц), а также при подключении клиента, если emissions включены.
- Если в `map_feed.yaml` нет блока `emissions` или `enabled: false`, кадров
  `emission_grid` нет и viewer работает как этап 2b.
- Кадр крупный (≈290 КБ при 120×90 и пяти поллютантах), поэтому клиент хранит
  только последний кадр в `EmissionBuffer`; float-массивы не попадают в React.

## `emission_grid`

Аддитивное расширение v1 (Этап 2c): карта приземных концентраций. Приходит с
частотой `emissions.grid_hz` (по умолчанию 1 Гц), только если симулятор включён
в `map_feed.yaml`.

```json
{
  "type": "emission_grid",
  "timestamp": 1793776800000,
  "unit": "ug/m3",
  "bounds": { "west": 5.9740, "south": 45.5268, "east": 5.9757, "north": 45.5277 },
  "cols": 120,
  "rows": 90,
  "fields": {
    "NOx":   { "data": "<base64>", "max": 719.0, "mean": 1.2, "p95": 169.0 },
    "CO":    { "data": "<base64>", "max": 8291.0, "mean": 11.0, "p95": 2062.0 },
    "PM2.5": { "data": "<base64>", "max": 12.0, "mean": 0.1, "p95": 3.0 },
    "PM10":  { "data": "<base64>", "max": 24.0, "mean": 0.2, "p95": 6.0 },
    "CO2":   { "data": "<base64>", "max": 9000.0, "mean": 40.0, "p95": 1200.0 }
  }
}
```

- `unit` — `ug/m3` для всех полей.
- `bounds` — `[west, south, east, north]` в градусах WGS-84.
- `cols` × `rows` — размер сетки; `data` — ровно `cols × rows` значений
  `float32` little-endian, закодированных в base64. Строки идут **с юга на
  север** (row-major), viewer переворачивает их при растеризации.
- `max`, `mean`, `p95` — статистика поля в мкг/м³; `p95` считается только по
  ненулевым ячейкам.
- Поля необязательны по отдельности: если поле отсутствует или его `data`
  битая, клиент отбрасывает только это поле. Кадр без единого валидного поля
  игнорируется.
- Клиент ограничивает размер растра (`cols × rows ≤ 4 000 000`), чтобы битый
  кадр не вызвал неконтролируемую аллокацию.

Viewer хранит растр в мутабельном `emissionBuffer` и обновляет deck.gl-слой из
`requestAnimationFrame`, не прогоняя массивы через React. Панель показывает
переключатель слоя, выбор загрязнителя, легенду и статистику.

## `heartbeat`

```json
{ "type": "heartbeat", "timestamp": 1793776800000 }
```

Клиент считает соединение живым, пока приходят любые кадры. Если в течение
`VITE_WS_TIMEOUT_MS` (по умолчанию 60 000 мс) не пришло ни одного кадра,
сокет закрывается и переподключается.

`MapFeed::Heartbeat` реализован, но `map_gateway` v1 его пока не вызывает,
поэтому `feed.heartbeat_s` в конфиге не действует. Увеличенный таймаут не даёт
переподключаться во время паузы в данных или после конца replay.

## Поведение клиента

- Переподключение с экспоненциальной задержкой 1 → 2 → 4 … 30 с и джиттером.
- Битые кадры пропускаются (предупреждение в консоль не чаще раза в 5 с).
- Треки без обновлений дольше `VITE_TRACK_TTL_MS` (по умолчанию 8 с) удаляются.
- Высокочастотные данные не попадают в React: они пишутся в `TrackBuffer`,
  deck.gl обновляется из `requestAnimationFrame`. Концентрации — в отдельный
  `EmissionBuffer` с тем же принципом.
- `emission_grid` раз в секунду заменяет последний кадр в `EmissionBuffer`;
  растр рисуется `BitmapLayer` поверх карты, панель концентраций обновляется
  из `emissionStore` (низкая частота).
- При `VITE_MAP_AUTOFIT=true` (по умолчанию) карта один раз подстраивается под
  первые `camera_zones`, а если зон нет — под первые треки. Это позволяет
  переключаться между Aire и Auburn без правки `.env` (при смене набора данных
  перезагрузите страницу).

## Реализация backend (`map_gateway` v1)

Gateway отправляет `tracks_update`, `camera_zones`, `tracks_remove`,
`emission_grid` (если включён блок `emissions`), `id_merge` (зарезервирован) и
`heartbeat` (реализован, но пока не вызывается). Сообщений `hello`,
`server_stats` и `track_detail` нет.
`camera_uid`, `trail_t`, `confidence`, `is_static` и `removed` внутри
`tracks_update` тоже не передаются. При подключении клиент получает
`camera_zones`, затем `tracks_update` с `mode: "snapshot"` и, если emissions
включены, актуальный `emission_grid`.
